# k6 채팅 부하 테스트

이 테스트는 Docker Compose로 실행한 두 Spring Boot 인스턴스에 접속해 로그인, WebSocket 연결, STOMP 구독 및 메시지 전송을 검증합니다. VU(가상 사용자)는 8080/8081 인스턴스에 번갈아 연결하므로 Redis Pub/Sub 메시지 중계 경로도 함께 테스트할 수 있습니다.

## 사전 준비

- Docker Desktop 실행
- 프로젝트 루트에서 `docker compose up --build -d`
- [k6](https://grafana.com/docs/k6/latest/set-up/install-k6/) 설치
- 테스트 포트 8080과 8081이 접근 가능한지 확인

## 실행

PowerShell에서 프로젝트 루트 기준으로 실행합니다.

```powershell
k6 run -e BASE_URL_1=http://localhost:8080 -e BASE_URL_2=http://localhost:8081 k6/chat-load.js
```

테스트가 시작되면 스크립트가 테스트 전용 사용자를 생성하고, 채팅방을 만든 뒤 app-2에서도 해당 방에 참여시킵니다. 테스트 사용자의 비밀번호는 스크립트 내부의 테스트 전용 값이며 실제 계정에 사용하지 마세요.

## 기본 부하 설정

초기 설정은 가벼운 로컬 테스트용입니다.

- 20초 동안 VU 1명에서 5명까지 증가
- 40초 동안 VU 5명 유지
- 마지막 20초 동안 종료
- 각 VU는 WebSocket 연결 후 약 2초마다 메시지를 전송

처음부터 큰 동시 접속 수를 지정하지 말고, 로컬 환경에서 정상 작동을 확인한 뒤 단계적으로 올리세요.

## 주요 지표

- `chat_messages_sent`: 테스트에서 전송한 메시지 수
- `chat_messages_received`: WebSocket을 통해 수신한 메시지 수
- `chat_message_delivery_ms`: 테스트 메시지의 송수신 지연 시간(가능한 경우)
- `websocket_connected`: WebSocket 연결 성공률
- `http_req_failed`: HTTP 요청 실패율

## 주의사항 및 해석

- 테스트는 로컬 PC의 CPU·메모리, Docker 자원, DB 상태에 영향을 받습니다. 결과를 운영 환경의 처리량으로 일반화하지 마세요.
- HTTP 세션은 인스턴스 간 공유되지 않으므로 스크립트는 각 인스턴스에 개별 로그인합니다.
- 테스트 사용자와 채팅방은 DB에 생성됩니다. 반복 테스트 시 테스트 계정/방이 누적될 수 있으므로 개발 DB에서만 실행하세요.
- 메시지 지연 시간 지표는 자신이 보낸 테스트 메시지를 수신한 경우를 기준으로 기록하며, 모든 환경에서 모든 메시지의 지연이 기록되는 것은 아닙니다.
- 이 스크립트는 초기 부하 검증용입니다. 결과를 확정하기 전, 서버 로그와 DB에 저장된 메시지 수 및 수신 수를 함께 확인하세요.
